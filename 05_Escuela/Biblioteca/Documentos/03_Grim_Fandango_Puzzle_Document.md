- **Qué se aprende:**
  - Un documento **monotemático**: sólo puzzles y personajes. Demuestra que conviene fragmentar el GDD por subsistema en vez de un mamotreto único.
  - Cómo se documenta una cadena de puzzles de aventura gráfica: dependencias entre objetos, estados y gating de progreso.
  - Ilustración integrada al texto de diseño (Peter Chan) — el dibujo como parte de la especificación, no decoración.
  - Tono autoral dentro de un doc técnico: el humor de Schafer sobrevive en el documento y funciona como alineador de equipo.
- **Gap de Vaultrum que cubre:** plantilla real de spec por subsistema (puzzles/progresión) para Game Design y Level Design.
