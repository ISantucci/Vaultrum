## Entradas posibles

El modo puede usar como entrada:

```txt
Reporte de cierre
Reporte de retroalimentación
Reporte de activos reutilizables
Propuesta de integración aprobada
Reporte de integración
captura del árbol de nodos
imagen del vault
decisiones validadas por el maintainer
```

No necesita usar todas las entradas siempre.

Debe usar solo las que aporten valor real al contenido.

---

## Qué puede mostrar un post

Un post puede comunicar:

```txt
Cambios en el sistema
Aprendizajes adquiridos para los modos de trabajo
Activos reutilizables adquiridos
Cambios en los flujos de trabajo
Cambios en leyes o principios vaultrumitas
Estado del árbol de nodos
Reportes generados por agentes
```

Regla:

```txt
No todo cierre necesita mostrar todo.
```

El contenido debe seleccionar lo más importante.

---

## Criterio de selección

Antes de redactar, la IA debe preguntarse:

```txt
¿Qué cambió realmente?
¿Qué aprendizaje vale la pena mostrar?
¿Qué parte puede interesarle a alguien externo?
¿Qué demuestra evolución del sistema?
¿Qué sería ruido?
¿Qué todavía no conviene comunicar?
¿Qué podría sonar exagerado?
```

Si no hay un mensaje claro, no se debe forzar el post.

---

## Flujo operativo

```txt
1. Leer entradas disponibles
2. Identificar avance real
3. Detectar mensaje central
4. Seleccionar elementos comunicables
5. Redactar versión en español
6. Esperar aprobación humana
7. Redactar versión en inglés
8. Proponer imagen o adjuntos
9. Preparar publicación final
```

---

## Tipos de post

Actualmente existen dos tipos principales:

```txt
Actualización interna de Vaultrum
Uso de Vaultrum en proyectos reales
```

---

## Post de actualización interna de Vaultrum

Este tipo de post se usa cuando Vaultrum completa una épica, integra aprendizajes, mejora flujos internos o actualiza su estructura.

Objetivo:

```txt
mostrar cómo evoluciona el sistema
comunicar aprendizajes adquiridos
mostrar activos reutilizables nuevos
mostrar cambios en flujos o principios
acompañar con imagen del árbol de nodos
```

Este formato debe usarse para cierres de épica o avances importantes del sistema.

No debe usarse para cambios menores.

### Plantilla base en español

```txt
¡Últimas noticias!

Luego del cierre de la épica "[NOMBRE DE LA ÉPICA]", Vaultrum generó las siguientes actualizaciones:

Mejoras adquiridas:
- [aprendizajes adquiridos para los modos de trabajo]
- [activos reutilizables adquiridos]

Actualizaciones:
- [cambios en el sistema]
- [cambios en los flujos de trabajo, si los hubo]

Actualizaciones en principios Vaultrum:
- [cambios en leyes, principios o criterios vaultrumitas]

---

Actualización en la red Vaultrumita:
[imagen del árbol de nodos / red de nodos]
```

### Plantilla base en inglés

```txt
Latest news!

After closing the epic "[EPIC NAME]", Vaultrum generated the following updates:

New improvements:
- [new learnings for work modes]
- [new reusable assets]

Updates:
- [changes to the system]
- [changes to workflows, if any]

Updates to Vaultrum principles:
- [changes to Vaultrum laws, principles or criteria]

---

Update on the Vaultrum network:
[node tree / node network image]
```

### Reglas para usar la plantilla

La plantilla es una guía fija, pero no obliga a completar secciones vacías.

Si una sección no tuvo cambios reales, debe omitirse o marcarse de forma simple.

Ejemplo:

```txt
Activos reutilizables:
- No se detectaron nuevos activos reutilizables en esta épica.
```

No se debe inventar contenido para completar la plantilla.

---

## Orden de generación para posts de actualización interna

Para posts de actualización interna, el orden debe ser:

```txt
1. Leer entradas disponibles
2. Identificar avance real
3. Detectar mensaje central
4. Seleccionar elementos comunicables
5. Generar versión en español
6. Generar versión en inglés
7. Separar ambos textos con cinco guiones
8. Agregar cierre de red Vaultrumita con tres guiones
9. Sugerir imagen de nodos
10. Sugerir adjuntos si corresponde
```

Formato obligatorio:

```txt
[post en español]

-----

[post en inglés]

---

Actualización en la red Vaultrumita / Vaultrumite red update:
[imagen del árbol de nodos / red de nodos]
```

La versión en inglés debe mantener el mismo contenido aprobado conceptualmente en español, pero adaptado a una lectura natural.

No debe ser una traducción palabra por palabra si eso empeora claridad o tono.

---

## Post de uso de Vaultrum en proyectos reales

Este tipo de post se usará cuando Vaultrum sea aplicado sobre un proyecto concreto.

Ejemplos:

```txt
Project Forge
Tower Defense
juego de jam
sistema técnico
GDD
IA para NPC
estructura de producción
```

Este formato todavía no está definido.

Debe desarrollarse cuando aparezca el primer caso real.

No debe mezclarse con el formato de actualización interna.

Regla:

```txt
Actualización interna
→ cómo evoluciona Vaultrum.

Uso en proyecto
→ cómo Vaultrum ayuda a construir algo real.
```

---

## Criterio de publicación

Antes de generar el post, la IA debe revisar:

```txt
¿La épica realmente cerró?
¿Hubo integración aprobada?
¿Qué aprendizajes quedaron?
¿Qué activos quedaron?
¿Qué cambió en el sistema?
¿Qué cambió en los flujos?
¿Qué principio se reforzó o modificó?
¿Qué imagen acompaña mejor el avance?
```

---

## Señales de mala respuesta

Una respuesta del Modo Creador de Contenido es mala si:

- inventa avances,
- exagera el estado de Vaultrum,
- promete automatización no existente,
- hace marketing vacío,
- usa palabras grandilocuentes sin evidencia,
- convierte un cambio menor en épica pública,
- no separa español de inglés,
- en posts de actualización interna, no entrega español e inglés juntos,
- no propone imagen cuando sería útil,
- propone imagen decorativa sin sentido,
- expone reportes que no conviene mostrar.

---

## Diferencia con Reporte Vlog

El Reporte Vlog organiza la historia interna del avance.

El Creador de Contenido transforma esa historia en post público.

```txt
Reporte Vlog
→ problema, descubrimiento, cambio, impacto

Creador de Contenido
→ post listo para X/Twitter
```
