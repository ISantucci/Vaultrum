## Requerimiento

[[RQ-002.5_Estados_Menus]] — estados de juego, menús y opciones.

## Objetivo del sistema

Que el juego tenga principio, medio y fin, y que el jugador siempre sepa dónde está y cómo salir de ahí. Es el requerimiento que separa una entrega de una demo técnica.

## Experiencia esperada

Entrás y hay un menú, no una partida ya empezada. Nunca quedás atrapado en una pantalla. Pausar detiene el juego de verdad.

## Reglas

1. Máquina de estados **explícita y única**. Un solo estado activo a la vez.

   ```txt
   Menu ──jugar──────► Countdown ──► Playing ──Scored──► PointScored
     ▲ ▲                  ▲             │ │                  │
     │ └──opciones──► Options           │ └──Esc──► Paused ───┤
     │                                  │              │      │
     │                                  └──────────────┘      │
     │                                    (reanudar)          │
     └──────── GameOver ◄────(alguien llegó a scoreToWin)─────┘
                  └──revancha──► Countdown
   ```

2. **El estado gobierna qué se actualiza.** No hay objetos que se auto-tickeen y consulten el estado: el manager tickea lo que corresponde a cada estado. En `Paused` no corre nada de gameplay.
3. Pausar usa el estado, **no** `Time.timeScale = 0`. `timeScale` está reservado para el micro-congelamiento del gol; usarlo también para pausa mezcla dos responsabilidades y produce bugs cruzados.
4. **Ninguna pantalla sin salida.** Toda pantalla tiene una acción de retroceso explícita, y `Esc` siempre hace lo esperable en cada contexto.
5. La cuenta regresiva ocurre antes de **cada** saque (inicio de partida y post-punto), no solo al empezar.
6. Los cambios de opciones se aplican a la **partida siguiente**, no a la que está en curso. Cambiar el balance a mitad de partida es injusto (pilar 5).
7. Las opciones se editan sobre una copia en memoria de la configuración, **no** sobre el asset. El asset es el default, no el estado de la sesión.

## Entradas

| Contexto | Tecla | Acción |
|----------|-------|--------|
| Menú / Opciones / Fin | `↑` `↓` | mover selección |
| Menú / Opciones / Fin | `←` `→` | ajustar valor (solo en Opciones) |
| Menú / Opciones / Fin | `Enter` / `Espacio` | confirmar |
| Menú / Opciones / Fin | `Esc` | volver |
| Playing | `Esc` | pausar |
| Paused | `Esc` | reanudar |

## Salidas / feedback

- Cada estado tiene una pantalla propia inconfundible; nunca dos overlays a la vez.
- La opción seleccionada se distingue por color **y** por un marcador `▸` (no solo por color: pilar 4, accesibilidad).
- La cuenta regresiva muestra `3 · 2 · 1` con estirón por tick, y la pelota visible y quieta en el centro.
- Al pausar, el juego se atenúa detrás del overlay para que se lea que está detenido y no trabado.

## Estados

| Estado | Se tickea | Sale por |
|--------|-----------|----------|
| `Menu` | UI | jugar → `Countdown` · opciones → `Options` · salir |
| `Options` | UI | `Esc` / volver → `Menu` |
| `Countdown` | paletas, temporizador | fin del conteo → `Playing` |
| `Playing` | paletas, pelota, cámara | `Scored` → `PointScored` · `Esc` → `Paused` |
| `Paused` | UI | reanudar → `Playing` · menú → `Menu` |
| `PointScored` | nada (respiro) | fin del respiro → `Countdown` o `GameOver` |
| `GameOver` | UI | revancha → `Countdown` · menú → `Menu` |

## Parámetros configurables

| Parámetro | Valor inicial | Rango |
|-----------|---------------|-------|
| `countdownSteps` | 3 | 1 – 5 |
| `countdownStepDuration` | 0.6 s | 0.3 – 1.5 |
| `pointPauseDuration` | 0.9 s | 0.3 – 2 |

Opciones expuestas al jugador: `scoreToWin`, `initialSpeed` (velocidad de pelota), `paddleSpeed` (velocidad de paleta), volumen.

## Integraciones

Gobierna a todas las demás. Es el único sistema que decide qué corre.

## Lectura por pilares

| Pilar | Lectura |
|-------|---------|
| 1 Core loop | Define el ciclo completo: menú → partida → resultado → otra vez. |
| 2 Victoria/derrota | `GameOver` es donde la victoria se declara y se nombra. |
| 3 Feedback | Cada transición tiene feedback; la cuenta regresiva es feedback de "prepárate". |
| 4 Claridad | **Pilar dominante.** El jugador siempre sabe en qué estado está y cómo salir. |
| 5 Justicia | Las opciones no se aplican a mitad de partida; la cuenta regresiva evita saques sorpresa. |
| 6 Dificultad | Vía opciones, en manos del jugador. |
| 7 Recompensa | La pantalla de fin nombra al ganador: es el cierre del arco. |
| 8 Pacing | **Pilar clave.** `Countdown` y `PointScored` son los valles que hacen que los picos se sientan. |
| 9 Agencia | El jugador elige largo de partida y velocidades antes de jugar. |

## Criterios de validación

- Play → aparece el menú principal, nada se mueve.
- Desde cada una de las 7 pantallas/estados hay un camino de vuelta al menú en ≤ 2 acciones.
- En `Paused` la pelota no avanza ni un pixel (verificable pausando a mitad de rally).
- Cambiar `scoreToWin` en opciones se refleja en la partida siguiente y no en la actual.
- No existe combinación de teclas que deje dos overlays visibles a la vez.
